Kubernetes Deployment Guide

Panduan step-by-step deploy aplikasi ke Kubernetes dari manual deployment sampai CI/CD. Dibuat untuk developer yang ingin paham alurnya, bukan cuma copy-paste YAML lalu berdoa. DevOps bukan dukun, bro.

Step 1

Cek Koneksi Cluster

Pastikan terminal sudah terhubung ke Kubernetes cluster yang benar.

terminal 
kubectl cluster-info
kubectl get nodes
Kalau node muncul, berarti koneksi aman. Kalau error, biasanya kubeconfig belum benar.
Step 2

Buat Namespace

Namespace digunakan untuk memisahkan environment atau aplikasi.

terminal 
kubectl create namespace my-app
kubectl get ns
Step 3

Buat Deployment

Deployment bertugas menjaga pod tetap hidup dan mengatur update aplikasi.

k8s/deployment.yaml 
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend
  namespace: my-app
spec:
  replicas: 2
  revisionHistoryLimit: 5
  selector:
    matchLabels:
      app: frontend
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 0
      maxSurge: 1
  template:
    metadata:
      labels:
        app: frontend
    spec:
      containers:
        - name: frontend
          image: registry.example.com/my-app/frontend:v1.0.0
          ports:
            - containerPort: 80
          resources:
            requests:
              cpu: "100m"
              memory: "128Mi"
            limits:
              cpu: "500m"
              memory: "512Mi"
terminal 
kubectl apply -f k8s/deployment.yaml
kubectl get pods -n my-app
kubectl get deploy -n my-app
Step 4

Buat Service

Service memberi alamat stabil untuk pod. Pod boleh ganti IP, service tetap jadi pintu masuk.

k8s/service.yaml 
apiVersion: v1
kind: Service
metadata:
  name: frontend-service
  namespace: my-app
spec:
  type: ClusterIP
  selector:
    app: frontend
  ports:
    - port: 80
      targetPort: 80
terminal 
kubectl apply -f k8s/service.yaml
kubectl get svc -n my-app
Step 5

ConfigMap

ConfigMap dipakai untuk konfigurasi non-rahasia seperti URL API, environment, atau nama aplikasi.

k8s/configmap.yaml 
apiVersion: v1
kind: ConfigMap
metadata:
  name: frontend-config
  namespace: my-app
data:
  APP_ENV: "production"
  API_URL: "https://api.example.com"
terminal 
kubectl apply -f k8s/configmap.yaml
Step 6

Secret

Secret dipakai untuk data sensitif seperti API key, password, token, dan credential.

terminal 
kubectl create secret generic frontend-secret \
  --from-literal=API_KEY=ini_api_key_rahasia \
  -n my-app
Step 7

Deployment dengan ConfigMap & Secret

bagian container 
envFrom:
  - configMapRef:
      name: frontend-config
  - secretRef:
      name: frontend-secret

Tambahkan bagian tersebut di dalam container deployment.

Step 8

Cek Logs & Debugging

terminal 
kubectl logs -f deployment/frontend -n my-app
kubectl describe pod nama-pod -n my-app
kubectl exec -it nama-pod -n my-app -- sh
Kalau error ImagePullBackOff, cek image registry. Kalau CrashLoopBackOff, cek log aplikasi.
Step 9

Scale Up & Scale Down

terminal 
kubectl scale deployment frontend --replicas=5 -n my-app
kubectl scale deployment frontend --replicas=2 -n my-app
kubectl get pods -n my-app
Step 10

Rolling Update & Rollback

terminal 
kubectl set image deployment/frontend frontend=registry.example.com/my-app/frontend:v1.0.1 -n my-app
kubectl rollout status deployment/frontend -n my-app
kubectl rollout history deployment/frontend -n my-app
kubectl rollout undo deployment/frontend -n my-app
Step 11

Ingress

Ingress dipakai agar aplikasi bisa diakses dari luar cluster memakai domain.

k8s/ingress.yaml 
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: frontend-ingress
  namespace: my-app
spec:
  rules:
    - host: frontend.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: frontend-service
                port:
                  number: 80
Step 12

CI/CD Flow

Push Code
Build Image
Push Registry
Deploy K8s
Rolling Update
Step 13

GitLab CI/CD

.gitlab-ci.yml 
stages:
  - build
  - deploy

variables:
  IMAGE_NAME: registry.example.com/my-app/frontend
  NAMESPACE: my-app
  DEPLOYMENT_NAME: frontend
  CONTAINER_NAME: frontend

build_image:
  stage: build
  image: docker:latest
  services:
    - docker:dind
  only:
    - main
  script:
    - docker build -t $IMAGE_NAME:$CI_COMMIT_SHORT_SHA .
    - docker push $IMAGE_NAME:$CI_COMMIT_SHORT_SHA

deploy_production:
  stage: deploy
  image: bitnami/kubectl:latest
  only:
    - main
  script:
    - kubectl config use-context production
    - kubectl apply -f k8s/
    - kubectl set image deployment/$DEPLOYMENT_NAME $CONTAINER_NAME=$IMAGE_NAME:$CI_COMMIT_SHORT_SHA -n $NAMESPACE
    - kubectl rollout status deployment/$DEPLOYMENT_NAME -n $NAMESPACE
