04 / Setup Environment: VirtualBox & Ubuntu Server

Spesifikasi Alokasi Resource VM

Implementasi deployment lokal menggunakan hypervisor Oracle VirtualBox dengan parameter isolasi hardware sebagai berikut:

  • Alokasi Prosesor : Min. 3 vCPU
  • Alokasi Memori : 4GB RAM
  • Alokasi Storage : 50GB Virtual Disk

Konfigurasi Guest OS

Menggunakan **Ubuntu Server** sebagai operating system dasar di dalam VirtualBox. Konfigurasi awal mencakup pemutakhiran paket kernel repository, pembuatan user non-root dengan hak akses sudoers, serta aktivasi VirtualBox Guest Additions untuk integrasi eksternal folder file-sharing host OS.

05 / Linux System Administration Fundamental

Definisi & Core Objective

Linux System Administration adalah pilar operasional untuk mengelola, mengatur, mengamankan, dan merawat server berbasis Linux. Fokus utamanya adalah memastikan stabilitas sistem (uptime), optimasi alokasi resource (CPU, RAM, Storage), manajemen akses pengguna (multi-user authorization), serta pengamanan lingkungan server dari celah eksploitasi eksternal.

Sistem Operasi Server

Berbeda dengan sistem operasi ber-GUI, Linux beroperasi langsung pada layer kernel CLI yang hemat resource, menjadikannya standar baku infrastruktur production server secara global.

Resource Health Check

Monitoring berkala terhadap proses yang berjalan, pemakaian RAM swap space, dan I/O disk storage mutlak dilakukan guna mencegah kegagalan sistem akibat kehabisan resource.

08 / Secure Shell (SSH) Architecture & Network Topology

Protokol Enkripsi Akses Jarak Jauh

SSH (Secure Shell) bekerja pada Application Layer (Default Port 22) untuk mengontrol host server jarak jauh melalui saluran komunikasi terenkripsi kriptografi asymmetric key pair (Public & Private Key).

Elemen Jaringan & Keamanan

  • SSH Client & Server: Pengirim request (Laptop) melakukan jabat tangan kriptografi ke daemon SSH Server (sshd) di dalam target VM.
  • Layer Firewall: Keamanan berlapis yang dikelola oleh Security Group (Gerbang utama network) dan lokal Firewall/IPTables (Satpam internal sistem).

Analisis Kegagalan Koneksi

  • Connection Timed Out: Request tertahan di layer terluar akibat aturan Firewall/Security Group yang memblokir akses port.
  • Connection Refused: Paket data mencapai host, namun service daemon SSH Server mati atau tidak mendengarkan Port 22.
  • Permission Denied: Kegagalan otentikasi keypair atau kecacatan hak akses user.

09 / Konsep Isolasi: Virtual Machine vs Container

Mekanisme Abstraksi Hardware dan Operating System

VM adalah emulasi komputer lengkap yang berjalan di atas software bernama hypervisor. Perbedaan mendasar terletak pada level abstraksi dan efisiensi pembagian instruksi komputasi host.

Virtual Machine (Hypervisor-Based)

  • Abstraksi pada level physical hardware via Hypervisor.
  • Setiap instance VM mewajibkan instalasi penuh Guest OS secara utuh lengkap dengan struktur Kernel tersendiri.
  • Resource allocation bersifat kaku (hard-allocated) sehingga beban overhead sistem sangat tinggi.

Container (Docker)

  • Abstraksi langsung pada level User Space di atas Kernel Host OS menggunakan fitur native kernel Linux: namespaces (isolasi network, pid, mount) and cgroups (pembatasan kuota CPU/RAM).
  • Tidak memerlukan duplikasi Guest OS; berukuran sangat kecil (megabytes) dan aktif dalam hitungan milidetik.

10 / Kapan Menggunakan VM vs Docker Container di Production

Pakai VM ketika:

  • Butuh isolasi penuh sampai level OS and kernel.
  • Menjalankan OS berbeda dalam satu host (misalnya Linux dan Windows).
  • Menjalankan aplikasi legacy yang sulit di-containerize.
  • Membutuhkan driver, kernel module, atau konfigurasi OS khusus.
  • Kebutuhan compliance dan keamanan server yang sangat ketat.

Pakai Docker Container ketika:

  • Menjalankan aplikasi modern (web, API, microservices).
  • Membutuhkan deployment yang cepat dan konsisten di tiap env.
  • Ingin efisiensi alokasi resource komputasi server.
  • Membutuhkan scaling horizontal secara dinamis (e.g. Kubernetes).
  • Membangun infrastruktur otomatisasi CI/CD pipeline.
  • Menjalankan aplikasi stateless/service yang mudah direplikasi.

Pola Arsitektur Global Production Server: VM + Docker

Di dunia nyata industri, strateginya adalah gabungan keduanya: VM digunakan sebagai server host, dan Docker berjalan di dalam VM.

Server Fisik (Baremetal) └── VM Ubuntu (Resource Host) └── Docker Engine (Container Runtime) ├── Frontend Container ├── Backend API Container ├── Nginx Reverse Proxy └── Database Core Engine

11 / Docker Runtime Engine & Isolation Core

Definisi Platform Docker

Docker adalah platform terintegrated yang berfungsi membungkus kode aplikasi beserta seluruh dependensi library-nya ke dalam satu unit container steril terisolasi, memastikan aplikasi berjalan konsisten di semua env server host.

Komponen Arsitektur Client-Server

  • Docker CLI: Komponen antarmuka pengguna tempat perintah diketikkan (seperti docker run).
  • Docker Daemon (dockerd): Proses background persisten yang mengelola siklus objek Docker (Images, Containers, Volumes, Networks).
  • Docker Hub Registry: Repositori pusat pendistribusian Docker Images secara global.

Isolasi Environment Aplikasi

Tanpa Docker, berbagai runtimes (Java, Node, Python, Postgres) bercampur langsung di dalam satu sistem operasi host, memicu potensi *dependency hell*. Docker mengisolasi tiap runtime ke dalam ruang kontainer yang steril.

13 / Menulis Dockerfile Efisien & Layer Caching

Definisi Teknis: Dockerfile merupakan skrip otomasi blueprint langkah demi langkah untuk membangun sebuah Docker Image secara berurutan.

FROM node:18-alpine # Base image minimalis WORKDIR /app # Set direktori utama aplikasi # Strategi Layer Cache: Salin manifes dependensi lebih dulu COPY package*.json ./ RUN npm install COPY . . # Salin sisa source code setelah dependensi aman EXPOSE 3000 CMD [ "npm", "run", "dev" ] # Runtime execution

Analisis Mekanisme Layer Caching

Docker membangun image secara berurutan per baris perintah (layer-by-layer).

Jika baris perintah atau isi berkas di atasnya tidak mengalami perubahan, Docker akan menggunakan Cache Layer yang sudah ada tanpa melakukan eksekusi ulang. Dengan menyalin package.json dan menjalankan npm install sebelum menyalin source code utama, proses instalasi dependensi akan di-skip oleh Docker selama tidak ada perubahan library di dalam file manifes. Proses build kompilasi menjadi jauh lebih cepat.
